# 文件操作测试安全约定

本次审计覆盖 Rust 单元测试、CLI 自检/端到端测试、GUI 测试，以及 Python 端到端、变异测试和打包脚本。

## 修复的风险

- 原先多个测试先删除 `%TEMP%` 下固定名称或仅含进程 PID 的目录，再创建夹具；进程号复用、遗留目录或其他程序的同名目录可能受影响。现已全部改成先原子创建本轮独占目录，绝不预删除已有路径。
- 哈希、快照和偏好设置测试原先直接覆写或删除固定临时文件；现统一置于本轮独占夹具目录。
- `tools/e2e_real.py` 和 `tools/muttest.py` 原先复用固定临时目录；现每次创建新目录，保留本轮产物供检查，不递归清理旧目录。
- 打包原先会删除 `.old` 目录、重命名并清理旧发布目录、删除旧 ZIP；现只原子创建新发布目录，ZIP 使用独占创建模式。`--name` 与旧产物冲突时直接拒绝覆盖；未指定名称时选择新的带后缀目录。

## Rust 测试夹具

统一使用 `core_io::test_dir::TestDir`：

1. 使用时间、PID 和原子计数生成候选名称，通过 `create_dir` 独占创建；名称冲突只重试，不打开或删除旧目录。
2. 在独占目录内写入本轮所有权标记，实际测试内容放在空 `data` 子目录，避免干扰文件数量、快照和实时事件断言。
3. 删除前校验规范化后的绝对路径、父目录边界、所有权标记，以及路径各层的符号链接/Windows reparse 属性。
4. 清理前检查整棵目录树，随后逐项复核并删除普通文件和空目录；不调用 `remove_dir_all`。发现所有权变化、链接、越界、特殊文件或读取错误时停止并保留目录，输出其位置。
5. 需要制造真实删除事件时，使用 `owned.remove_file("子目录/测试文件")`。只接受普通相对路径，拒绝 `..` 和绝对路径。

`TestDir` 仅用于本进程创建的短期测试夹具，不是通用用户目录清理器。不要将用户选择的监控目录纳入它的清理范围。保持 guard 活到监控线程和文件句柄释放之后。

## Python 测试夹具

`tools/safe_test_dir.py` 使用 `mkdtemp` 独占创建目录，保存本轮随机所有权标记，并在单文件删除前检查所有权、规范路径边界和所有祖先的链接/reparse 属性。所有输出保留，不调用递归清理。

`tools/test_safe_test_dir.py` 覆盖越界路径、`..`、所有权标记变化、真实符号链接拒绝，以及旧发布目录和 ZIP 保持不变。若 Windows 账户禁止创建符号链接，该单项测试明确显示跳过。

## 已审核的运行范围

```powershell
cargo test --workspace
cargo test --manifest-path apps/gui/src-tauri/Cargo.toml
python -B -m unittest discover -s tools -p test_safe_test_dir.py -v
python -B tools/e2e_real.py target/x86_64-pc-windows-gnu/debug/filewatch.exe
python -B tools/check_api.py .
python -B tools/muttest.py
```

真实文件删除仅限这些用例本轮创建的夹具；监控、遍历、快照和去重仍读取测试夹具。CLI 参数检查和卷枚举测试不会删除系统数据。

系统 USN Journal 的 `--delete` 命令不在测试范围，本次未执行；它是影响整卷的管理操作，不能作为测试清理手段。`setup-rust.ps1` 仍包含安装程序临时文件的预删除，但不属于测试流程，本次未执行安装脚本。
