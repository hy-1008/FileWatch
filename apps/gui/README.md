# FileWatch GUI（Tauri 2 + Canvas）

引擎的可视化前端。**薄壳**：所有算法（扫描、聚合、布局、阈值）都在 `crates/**`，
这里只负责把引擎状态暴露成命令、把布局结果按二进制推给前端、把窗口开起来。

```
apps/gui/
├─ src-tauri/          Rust 侧（Tauri 应用）
│  ├─ src/main.rs      入口 + 命令注册 + `--check-elevation` 诊断
│  ├─ src/commands.rs  前端能调的命令（对应文档 F1~F12，另有 F0 权限）
│  ├─ src/state.rs     扫描结果的共享状态（含派生索引的「代数」对齐）
│  ├─ src/wire.rs      Rust → 前端的二进制布局协议（含对拍测试）
│  ├─ src/elevate.rs   管理员权限：检测 + runas 重启（手写 FFI）
│  ├─ src/prefs.rs     GUI 偏好落盘（%APPDATA%\FileWatch\gui-prefs.json）
│  ├─ src/monitor.rs   F6/F7/F8：轮询线程 + 环形缓冲 + CSV 导出
│  ├─ src/analyze.rs   F12 重复文件（后台线程 + 进度事件）+ F11 快照与快照对比
│  └─ icons/icon.ico   必需（见下）
├─ src/                前端（纯静态，无打包器、无 npm）
│  ├─ index.html
│  ├─ style.css
│  ├─ wire.js          二进制协议的解码端
│  ├─ admin-rule.js    权限弹窗的触发规则（纯函数，可单独跑真值表）
│  ├─ view-rule.js     视图规则：扫描根 → 该点亮哪张盘符卡片（纯函数）
│  ├─ treemap.js       Canvas 渲染 + 命中测试 + 交互
│  └─ app.js           状态、各面板、中间区三个视图（面积图 / 重复文件 / 快照对比）
└─ tools/
   ├─ make-icon.py     生成 icons/icon.ico
   ├─ check-wire.js    线格式校验（按文档偏移造字节流 ←→ wire.js 解码）
   └─ check-admin.js   两条规则的纯函数真值表 + 与 Rust 侧字段对账 + 全界面 DOM 接线 + 栏位结构
```

## 构建与运行

```bash
# 1) 图标（只需生成一次；改了图案再跑）
python apps/gui/tools/make-icon.py

# 2) 编译（首次要下几百个依赖，约 15~20 分钟；之后增量几秒）
cd apps/gui/src-tauri
cargo build --release

# 3) 运行
./target/x86_64-pc-windows-gnu/release/filewatch-gui.exe
```

**产物在 `target/x86_64-pc-windows-gnu/release/` 而不是 `target/release/`** ——
因为引擎根的 `.cargo/config.toml` 把目标固定成了 `x86_64-pc-windows-gnu`，而
cargo 的配置是**从当前目录逐级向上**读取的，`src-tauri` 会继承到那一条。
（这与 CLI 的产物布局一致，是有意的。）

前端是**静态文件**（`tauri.conf.json` 的 `frontendDist` 直接指向 `../src`），
所以没有 Node / npm / Vite 这一套 —— 改完 HTML/JS 重新构建一次即可，
不需要 `tauri dev`。这也意味着不用装任何 npm 包。

**前端会自动触发重编，不用手动记得。** `tauri::generate_context!()`（`src/main.rs`）
在编译主 crate 时读取前端目录并把内容嵌进 exe，而这些源文件会被 rustc 记进
**dep-info**（`target/<triple>/release/.fingerprint/filewatch-gui-*/dep-bin-filewatch-gui`
里逐条列着 `..\src\app.js` 等），cargo 的 fingerprint 就建立在这份清单上 ——
所以「只改 HTML/JS、不动任何 `.rs`」也会 `Compiling filewatch-gui`。
实测确认过（`build.rs` 未动、只改 `src/view-rule.js`，那一次构建脚本并未重跑）。
因此 `build.rs` 里**不要**再补 `rerun-if-changed=../src`：多余，还会让构建脚本
白跑一遍、多编一次。

（顺带：Tauri 2 会把前端压缩后嵌入，所以 **exe 里 grep 不到明文** ——
别用「搜字符串」判断前端有没有编进去。）

### 自检

```bash
# Rust 侧：引擎 → 布局 → 二进制 的端到端，参数映射、权限检测、偏好落盘，
# 以及「真实目录 + 真实 ReadDirectoryChangesW」的监控端到端
cd apps/gui/src-tauri && cargo test --release

# 前端侧：解码端与线格式文档是否一致（830 条断言）
node apps/gui/tools/check-wire.js

# 前端侧：界面规则的纯函数真值表 + 全部 DOM 接线 + 模式/自启/周期任务/路径选择器对账（454 条断言）
node apps/gui/tools/check-admin.js

# 权限现状（不进界面、不开窗口，直接打 stdout）—— 排查 UAC 问题用
./target/x86_64-pc-windows-gnu/release/filewatch-gui.exe --check-elevation
```

界面点击没法自动化，所以「Rust 编码 / JS 解码」这条跨语言契约单独用
`check-wire.js` 钉住：它按**文档里的偏移**手工造字节流，再用 `wire.js` 解回来
逐字段对拍。加上 `wire.rs` 自己的往返测试，两侧都各自钉在同一份文档上。

`check-admin.js` 是同一思路用在两处**只在特定条件下才走得到**的规则上：

* 权限弹窗的触发规则：三条分支里有两条（"本次启动已尝试过提权"、"令牌未提权却仍算有权限"）
  只在关了 UAC 的机器上才走得到 —— 在这台开发机上永远点不出来。所以它把 3×2 的组合全跑一遍，
  并顺带从 `commands.rs` 里抠出 `ElevationInfo` 的字段名做对账。
* `view-rule.js` 的盘符归属：UNC 共享、`\\?\Volume{…}\` 这类路径在这台机器上不存在，
  判错的表现却是"卡片亮着，用户以为自己在看那块盘"。所以 16 种形态全跑一遍。

它还兼着一个更通用的职责：**`app.js` 里 `getElementById` 的每一个 id，都必须在
`index.html` 里真的存在**。id 打错这类问题 Rust 侧查不到、界面上又只是"点了没反应"，
是最容易漏的一种。现在 `index.html` 有 141 个 id、`app.js` 引用其中 123 个，
并且对权限窗、分析视图、第 1/2 栏这批关键 id 是**双向**对账（HTML 里少了会报，
HTML 里存在但没人接线也会报）。

最后还有两条**结构守卫**：

* **栏位结构**：盘符与文件夹树必须分别落在 `.panel.drives` 与 `.panel.left` 里、
  且不能同栏 —— 这是给一次真实重叠 bug 留的回归断言（见下一节）。
* **滚动条**：必须走自绘（`::-webkit-scrollbar` + 三个 `--sb-*` 变量），并且
  `scrollbar-width` / `scrollbar-color` **不得出现**（这两个标准属性一旦设置，
  Chromium 会整段忽略 `::-webkit-scrollbar`，界面悄悄退回 16px 的系统滚动条，
  不报错、只有滚动时才看见）。这是给一次"滚动条太难看"的返工留的守卫。

监控那一块则靠 `monitor.rs` 里的 `real_directory_change_reaches_the_ring`：
真的建会话、真的写文件、真的等 `ReadDirectoryChangesW` 把事件送上来。
这段的失败模式几乎全是"不报错、只是没反应"，夹具级测试全都会过，
**只有真挂一次目录监视才看得出来**。

## 版面：四栏 + 每栏的块高度策略

```
┌────────┬──────────┬────────────────────────────┬──────────────────┐
│ 盘符   │ 文件夹树 │ 面积图 / 重复文件 / 快照对比 │ 类型 · 大文件 ·   │
│ 一列   │          │ （三个页签共用整块）         │ 详情              │
├────────┴──────────┴────────────────────────────┴──────────────────┤
│ F6/F7/F8 实时监控抽屉（全宽；收起时只占一行）                        │
└───────────────────────────────────────────────────────────────────┘
```

盘符**单独一栏**、文件夹树**另一栏** —— 而不是当初那样两个块堆在同一个 `aside` 里。
改的理由是一次真实的重叠：两块都是"可被压扁"的 flex 项（`flex-shrink` 默认 1），
窗口一矮、或者挂载的卷一多，盘符那块的可用高度就先小于它自己的内容，而卡片没法再矮，
于是溢出块外、盖在下面的树上。**这类 bug 不会报任何错**，只能靠眼见。

现在每栏里的块只有两种高度策略，没有第三种：

| 类 | 高度 | 用在哪 | 为什么 |
|---|---|---|---|
| `.grow` | 吃掉剩余高度，内部滚动 | 盘符列表、文件夹树 | 它们是"要多少有多少"的列表 |
| 不带类，`flex: N 1 0` | 按权重分 | 右栏三块 | 内容高度只是**上限**（类型 60 行、大文件 200 行都是上限），拿它当基准会把「详情」挤成一条缝 |

三条配套的硬约束：

* 会滚动的容器必须**同时**有 `min-height: 0` 和 `overflow: auto`。少了它们，
  块再矮也不会滚，只会把内容画到块的外面 —— 这正是上面那个重叠的机制。
* 三个侧栏都加 `overflow: hidden`：栏与栏之间硬隔离。最坏情况是被自己裁掉一块，
  不可能盖到隔壁栏上面去。
* `.block.grow` 有 96 px 下限（表头 + 三行）。窗口最小 600 高、监控抽屉展开时，
  还能剩 172 px，所以这条下限不会被撑破。

盘符卡片是**一列**（不是两列）：一列才放得下「总共 / 可用」两行数字，而且数字右对齐，
窄栏里也不会被截成省略号。当前正在看的那块盘会点亮边框（`.vol.active`，
由 `view-rule.js` 判断归属），UNC / 卷 GUID 路径不会点亮任何一张。

## 盘符栏折叠（宽度守恒）

盘符栏标题栏**最右侧**有一个 chevron 按钮。点它之后第 1 栏收窄到 64px，省出来的
宽度**全部**给第 2 栏（文件夹树），中间区与右栏一像素都不动 —— 这条「宽度守恒」
不是巧合，是写法保证的：

* 两栏宽度都是 CSS 变量（`--drives-w` / `--left-w` / `--drives-w-collapsed`），
  窄屏媒体查询只改变量、折叠规则自动跟着走；
* 树的折叠宽度是 `calc(var(--left-w) + var(--drives-w) - var(--drives-w-collapsed))`，
  **不写死数字** —— 上面任何一个宽度改了，折叠态自动跟着对；
* 两个 `transition` 的时长与缓动完全相同，所以过渡期间 `drives + left` 恒等于
  原值，中间区在动画期间也是静止的，画布没有尺寸变化、**不需要**重算布局；
* 中间区/右栏**一条折叠规则都没有**（`check-admin.js` 有断言挡着）。

折叠态长这样：

* 标题栏只剩「盘符」+ 图标。图标整个 `rotate(180deg)` 掉头 —— 一份字形同时表示
  「收起」和「展开」，不会出现两个长得差不多的箭头；
* 每个卷缩成一根竖条：竖排盘符字母 + 一根自下而上的「占用水位」。字母是单独的
  `.glyph` 元素（竖排的 `C:` 里那个冒号看着像标点错了位）；已用比例走 CSS 变量
  `--used` —— **同一个数字横着是宽度、竖着是高度**，两种形态各自解释它，JS 只算一次；
* 横排的容量文字全部藏起（~52px 里必然全是省略号），悬停卡片的 `title` 里有
  `C:　NTFS　卷标 / 总共 / 可用` 全部信息。
  （原先钉在栏底的「扫描目录」输入框已删除 —— 见下一节，扫描入口只剩两处。）

折叠状态记在 `gui-prefs.json` 的 `drives_collapsed`（下次启动直接恢复，过渡动画
挂在 `body.drives-animated` 上、首帧之后才加，所以恢复不会补放一遍收拢动画）。
这涉及两件**必须做对**的事：

1. `prefs.rs` 的 `GuiPrefs` 挂了 `#[serde(default)]` —— 没有它，老配置文件
   （缺这个字段）会**整个**反序列化失败、退回默认值，用户升级一次就得重新点一遍
   「不再自动询问权限」；
2. 前端 `savePrefs()` 是**读-改-写**：后端 `set_gui_prefs` 收的是一整个
   `GuiPrefs`（整体替换），只把 patch 递过去的话，其余偏好会被默认值顶掉 ——
   表现是「切一下折叠，『不再询问权限』就没了，下次启动又弹窗」，且不报任何错。

前端用的偏好键名与 Rust 字段的对账也在 `check-admin.js` 里：键名写错一个大小写
（`drivesCollapsed` vs `drives_collapsed`）不会有任何报错 —— 存下去是后端不认识的
键、读出来永远是 `undefined`，表现是「折叠了，重启又展开」。

## 「模式」：运行模式 + 开机自启动 + 关闭软件

顶栏的「模式」是一个弹出面板（与「界面」同一套菜单），里面有三组东西：
**运行模式（轻量 / 标准 / 性能）**、**开机自启动**、**关闭软件**。底部状态栏另有
「可用 / 总空间」。把它们收在一处是因为它们都是"这个程序该怎么跑"的选择，不是
随手点的按钮 —— 开机自启的开关塞在顶栏时，要么看不见，要么被当成"立即启动"；
「关闭软件」的两个选项也没地方写清各自的后果。它们背后各有一条
**不许出现第二份实现**的规矩：

* **模式的数字只有一处定义。** `src-tauri/src/profile.rs` 定义 `Profile`（lean /
  balanced / performance）和由它派生的参数：面积图 LOD 阈值倍率、列表行数倍率、
  扫描要不要顺手建实时监视、侧栏要不要拖到空闲时加载、跑不跑后台周期任务。
  前端切换模式后调 `profile_budget` 把数字**取回去用**，自己不换算 ——
  行数缩放在 `commands::row_limit`（三个列表命令各自调用），
  前端传过去的 `limit` 是**基数**。`check-admin.js` 双向对账：下拉框的每个取值
  后端必须认识、后端定义的每个模式前端必须选得到。
* **轻量不是免费的。** 它省下的是实时监视的路径索引、更粗的 LOD（矩形少 →
  布局结果与 IPC 字节都少）、减半的列表行数；索引树本身（约 40 B/节点）是看
  面积图的前提，**省不掉** —— 这点写在 `cost_cn` 里，切换时以 toast 告诉用户。
* **性能模式会跑后台周期任务**（`scheduler.rs`）：每隔 N 分钟刷新一次全部盘符
  容量（推 `volumes:tick`），并按「轮转」扫一块盘。但**绝不**去扫用户正在看的那块
  **以外**的盘 —— 一次扫描会替换进程里唯一的扫描结果，后台扫 D 盘等于把用户正在
  看的 C 盘视图偷偷换掉。所以规则是：用户在看某块盘就刷新那一块；还没有任何
  扫描结果才轮转预取（这条有 Rust 单测钉着，`check-admin.js` 也有静态断言挡
  "逐个盘符无脑扫"的写法）。周期任务线程每秒醒一次看停止标志，退出时最多等它
  一秒出头 —— 一睡 60 分钟的线程是叫不醒的。
* **开机自启动的真相在注册表里**（HKCU 的 `Run` 键，`autostart.rs` 手写
  `advapi32` FFI）。它**不进偏好文件**：用户在任务管理器里关掉之后，偏好文件
  里还写着"开"就成了骗人的显示。命令行拼装带引号（路径含空格时不带引号会在
  登录时静默启动失败）；界面显示的是**写完之后**从注册表读回的状态 —— 写入可能
  被系统策略拦下，假装成功比失败更糟。便携包挪过位置时旧条目会失效
  （`stale`），界面会提示关掉再开一次。
* **关闭软件（最小化到托盘 / 关闭所有进程）** 是偏好里的一项
  （`close_behavior`，取值 `tray` / `quit`）。判定在**后端**
  （`tray.rs::handle_close_requested` 读落盘的偏好）：关窗口那一刻界面可能正忙
  （扫描中、事件洪水），"点 × 之后去哪"不该依赖前端还能不能跑。默认**退出** ——
  常规软件的关闭就该是关掉，常驻后台是个明确的选择。
  托盘图标**始终**存在，它的右键菜单里有「退出」：少了这条，"最小化到托盘"就会
  把程序变成一个关不掉的幽灵（窗口没了、进程还在、用户找不到它在哪）。
  未知取值一律解释成"退出"（`GuiPrefs::clamped`），宁可退出也不要藏起来。
* **阈值预警要"人不在跟前也看得见"**。监控的意义是"我不盯着时它替我盯"，
  所以命中阈值时做三件事（`tray.rs::notify_alert`）：
  1. **系统通知**（`tauri-plugin-notification`，Windows 通知中心）；
  2. **托盘图标闪动** —— 交替设置"右上角带红点"的图标与正常图标 6 次；
     告警图标是拿窗口图标现画的（`alarm_variant`），不另存一份资源。
     闪动用 `AtomicBool` 防重入：两条预警连着来不会互抢图标、最后停在告警态；
  3. **托盘右键菜单记下最近 5 条**，点任一条都由 `tray:open-monitor` 打开窗口
     并切到监控页签。菜单每次重建（`rebuild_menu`），文本压成单行并截断
     （长路径会把菜单撑出屏幕，连「退出」都找不到）。
  两条监控路径都接了：联动走 `monitor:tick` 的两处（轮询 + 收尾），
  独立监控在 `record` 里返回触发的文本、**锁放掉之后**再发（拿着 registry 锁
  去等主线程重建菜单是自找麻烦）。通知失败、图标被资源管理器重启丢掉，
  都只是"没提醒到"，不影响监控线程 —— 每一步都是 `let _ =`。

  通知弹没弹、图标闪没闪没法用单测覆盖，所以留了一个诊断入口：
  `FileWatch.exe --selftest-alert` —— 造一条假预警，走完整链路，把最近预警写进
  `%TEMP%\filewatch-alert-selftest.txt` 后自己退出。改这块代码时跑一次，
  至少能确认"记录 → 菜单重建 → 闪动线程 → 通知调用"这条线上没有 panic。

底部状态栏的「可用 / 总空间」来自**盘符容量**（`list_volumes`），不是索引里的
字节数 —— 后者是"扫到的文件加起来多大"，前者才是"这块盘还剩多少"。归属判断在
`view-rule.js` 的 `fwVolumeOfTarget`（纯函数，真值表在 `check-admin.js`）；
性能模式的后台刷新走同一条渲染路径（`renderVolumes` → `renderSpace`），
不会出现"后台刷一下界面就变个样"。

## 管理员权限（F0：进入软件时申请）

文档 R2 的原方案是嵌 `requireAdministrator` 清单自动提权。那个方案的问题不是
"做不到"，而是**代价**：每次双击都要过一遍 UAC（包括只想看一眼面积图的时候），
而且提权进程与资源管理器不在同一个完整性级别，拖放交互会静默失效。

这里改成**进入软件时问一次**：

| 情形 | 行为 |
|---|---|
| 已有管理员权限 | 直接进界面，状态栏显示绿色「权限：管理员」 |
| 在管理员组、被 UAC 过滤 | 弹窗 → 点「以管理员身份重启」→ Windows 弹确认框，**点「是」即可，不用输密码** |
| 不在管理员组 | 弹窗，但文案说明需要输入管理员账户的密码 |
| 用户点「以降级模式继续」 | 照常进界面，橙色「权限：降级模式」；点它可随时重新申请 |

实现要点（都在 `src-tauri/src/elevate.rs`）：清单保持 `asInvoker`，用户同意后用
`ShellExecuteW(verb="runas")` 重启自己；`ShellExecuteW` 会阻塞到用户在 UAC 框上
做出选择，所以整个动作放在**独立线程**里跑，结果用 `admin:relaunch` 事件回传，
界面在此期间不冻结。

三个容易写错、已经钉住的地方：

1. **不能只看令牌。** 系统关掉 UAC 时 `TokenElevationType` 是 `Default`、
   `TokenIsElevated` 为 0，但进程其实拿着完整令牌、卷照样打得开。所以判据是
   **令牌 ∨ `\\.\C:` 能不能打开**。只信令牌会在这类机器上每次启动都追问一遍。
2. **必须防死循环。** 重启时给新进程塞 `--elevation-attempted`；新进程见到它就
   不再自动弹窗（只提示一次"提权未生效"）。否则在"提权无效"的机器上会
   「弹窗 → 重启 → 又弹窗」转圈。
3. **命令行参数要正确加引号。** `--root=C:\Program Files\x` 直接拼会被拆成两个
   参数，新进程拿到错路径 —— 而且错得很安静。`elevate::quote_arg` 按
   `CommandLineToArgvW` 的规则处理（含"结尾连续反斜杠要翻倍"这条），单测覆盖。

「不再自动询问」落在 `%APPDATA%\FileWatch\gui-prefs.json`。读取一律容错
（文件缺失/截断/被手改成非法 JSON 都退回默认值）—— 一个偏好文件不该有能力让
程序起不来。**"不再自动问"不等于"没地方问"**：状态栏的按钮任何时候都能把窗调
回来，所以用户不会被自己的选择锁死。

## 实时监控（F6 增量 / F7 阈值预警 / F8 变更流水）

窗口底部的一个抽屉式面板。引擎侧**全部已具备**（与 CLI 的 `monitor` 命令同一套），
这一层只做三件事：驱动轮询、保存最近若干条、把变更与预警推给界面。

### 一个决定性的选择：监控挂在**同一棵**索引树上

监控会就地改索引树（新增/删除/改名/体积变化），而面积图、文件夹树都读这棵树。
如果给监控另开一个会话，就变成两棵树各说各话 —— 面积图永远看不到变化。

所以监控直接驱动当前会话。代价是两条硬规矩：

1. **扫描与监控互斥。** 扫描会换掉整棵索引树，所以监控中不能重新扫描（反过来也一样）。
   两边都会明确拒绝并说明原因，而不是让监控线程悄悄改一棵已经被丢弃的树。
2. **派生索引按「代数」对齐。** 树变了，`ChildIndex` / `ExtensionTable` 就过期了。
   每一份派生索引都记住自己是从哪一代建出来的，树挂一个代数计数器（监控每应用
   一批事件 +1）。谁要用派生索引就先 `refresh_derived()`，只在代数不匹配时重建。

   这样做两边都不吃亏：用户不动界面时一次重建都不发生；一旦要看，拿到的必然与
   当前树一致 —— **不存在"显示过期数据"这个状态**。前端也拿同一个代数决定
   要不要重画面积图（节流到 1.5 s 一次）。

### 没有事件源时会重新扫描一次

`Session::open` 在**建立会话时**就决定了增量从哪来（USN Journal / 目录监视 / 没有）。
界面上「同时建立实时监视」默认不勾（大目录上建路径索引是一笔真实开销），所以刚扫完的
会话很可能根本没有事件源 —— 那时 `poll` 只会空转，监控看起来"启动了但永远没动静"，
是最费时间的那种假象。

所以 `monitor_start` 会先检查：会话里有事件源就直接用；没有就**用带监视的配置重扫一次**
（进度复用扫描那条事件通道），并在回执里带 `reopened: true`，界面据此提示一句。
管理员 + NTFS 的机器上通常直接命中第一条，不会重扫。

### 其余几个小决定

* **环形缓冲 4000 条**在内存里，作为界面回放与 CSV 导出的数据源；多出来的按天
  落盘走引擎既有的 JSONL（勾「变更落盘」）。界面最多画 300 行，DOM 不跟着涨。
* **一轮最多推 100 行**给前端：事件风暴（解压、`git checkout`）时一轮可能上万条，
  全塞进 IPC 会把渲染线程淹掉（文档 R5）。被截断时界面会明说，并提示导出 CSV 看全部。
* **体积说法与路径都取自引擎**（`core_monitor::event_size_text` / `core_scan::paths`）：
  同一条变更在终端与界面上显示的数字必须一样，否则用户没法判断该信哪个。
* **退出时等监控线程收尾**（最多 1.2 s）：`Session::shutdown` 要吐出 debounce 池里
  剩下的变更并保存 USN 游标。不等的话，关窗口 = 丢掉最后几秒，下次启动还要从旧游标重放。
  另外每 30 s 落一次游标（`Session::checkpoint`），把"跑了一晚上被强制结束"的损失
  从几小时压到几十秒。
* **不引文件对话框插件**：导出路径用输入框 + 一个默认值（桌面）。为一个输入框拉一个
  `tauri-plugin-dialog` 不值得。

### 分析视图（F12 重复文件 / F11 快照对比 / F13 文件搜索）

中间区顶部有四个页签，共用整块区域：**面积图 / 重复文件 / 快照对比 / 文件搜索**。
面积图要的是"尽量大的画布"，另外三个要的是"尽量宽的表" —— 并排挤在一起两边都难受。

两个视图的 Rust 侧都在 `src-tauri/src/analyze.rs`，而**算法一行都不在这里**：
调的是 `core_scan::dedup` / `core_scan::snapshot`，也就是
`filewatch dupes` / `snapshot` / `diff` 用的同一份实现。

### F12：为什么必须放到后台线程

耗时取决于磁盘上**真正重复的数据量** —— 三级筛选会把不重复的文件完全跳掉，
但真重复的那部分总得读满一遍。机械盘上这可能是几分钟，所以：

* **不在命令里同步做**（会把界面冻住），而是开线程 + 推 `dup:progress` / `dup:done`
  / `dup:error` 三条事件。进度节流 60 ms，与扫描同一档。
* **不持有扫描结果的锁**：只把「路径 + 体积」的候选表**复制**出来就松锁。
  候选表是一份纯数据快照，监控线程随后怎么改索引树都不影响它 ——
  这是"分析视图与实时监控能同时用"的前提。
* **刻意不做中途取消**：取消要在线程里到处插检查点，还要回答"取消后结果算不算数"。
  这一步是只读的、不会留下半个文件，真要停直接关窗口即可。

**界面不解析体积单位。** 输入框里的 `1M` / `512K` 原样交给后端，由
`core_monitor::spec::parse_size` 解析 —— 与 CLI 的 `--min-size=1M` 是同一个函数。
前端自己写个正则的话，用户在终端里学会的写法到界面上就不认了，
而且这种分歧只在某个特定单位上才暴露。看不懂的写法**报错**，不静默退回 0
（那等于"写错单位 → 悄悄变成不设下限"，而用户以为自己设了 1 MB 的下限）。

**扫描期间不能开始查找**：扫描结束前索引树会被整体换掉，候选表就是过期数据。
后端直接拒绝并说明原因（界面上会弹提示），而不是让用户等到最后发现数字不对。
监控则**不受影响** —— 它是就地改树，候选表是一次性的只读复制，两者不冲突。

结果里有两处必须显眼提示的"不完整"：**候选数达到上限被截断**（还有文件没被比较过），
以及**读不到的文件数**。少了这两个数字，用户会把"至少这些是重复的"当成"就这些"。

### F11：方向固定，不提供"反着比"

界面上的对比是「**一份快照 → 当前的扫描结果**」，而不是"两份快照"。因为界面本来
就有一棵活着的索引树，让用户再存一份再去比是多余的步骤；方向固定也就不会看反。
（CLI 的 `diff` 是两个路径，因为命令行下没有"当前扫描结果"这个东西。）

三条提示直接写在列表头部，因为它们决定"这份结果能不能信"：

* **快照被截断过** → 没被记进去的文件会被判成「新增」。用户很可能照着这份清单
  去删实际上一直存在的文件，所以摘要、列表头、`#count` 校验三处都会说这一点。
* **两份数据的扫描根不同** → 不报错（换了挂载点确实可能要比），但显眼警告。
* **行数被 `top` 截断** → 明说"只列了 N / 共 M 行，导出 CSV 可看全部"。

导出的 CSV **不在这里生成**：`snapshot_compare` 返回时就带着引擎算好的正文，
「导出」只是把它写盘。否则界面显示的行与导出的行可能来自两次不同的计算。

### 一处收敛：时间口径（v0.1.3 起统一用**本地时间**）

F11 要生成"桌面 + 时间戳"的默认文件名。这个时间戳原来有三份实现
（CLI 的 `base_ms`、GUI 的 `commands::now_ms` 与 `monitor::now_ms`），
现在统一到 `core_io::util` 的 `unix_ms` / `unix_secs` / `local_stamp`，
并且进了 `check_api.py` 的 **I 类**（全工程只允许一处顶层定义）。
默认文件名也统一由一个命令给（`analyze_default_path`，kind = snapshot /
duplicates / diff），前端不再自己 `new Date()` 拼。

**为什么从 UTC 改成本地**：0.1.2 的对比页头部写的是 `2026-10-20 15:07:08Z`，
而任务栏是 `23:07` —— 用户的第一反应是"时间不对"。`std` 没有任何时区信息，
所以 `core_io::util::local_time` 在 Windows 上走 `SystemTimeToTzSpecificLocalTime`
（按目标时刻的夏令时规则换算，不是加固定偏移），其它平台退回带 `Z` 的 UTC 文本。
**两个坑**：FILETIME 的单位是 100ns，秒数还要乘 10⁷（漏了会得到 1601 年）；
`std` 的 `Duration` 与 `FILETIME` 都别自己移位，走 `local_systemtime` 一处。

前端只留一份实现：`fwLocalTime`（`view-rule.js`）。原来 app.js 里另有一份
`fmtTime`，**没有 Invalid Date 保护** —— 坏掉的 FILETIME 会被读成一个巨大的
负数，`new Date(负数*1000)` 是 Invalid Date，`getFullYear()` 返回 NaN，
界面上就印出 `NaN-NaN-NaN NaN:NaN`。现在 `fwLocalTime` 同时挡住
Invalid Date 与 1601~2200 之外的值（NTFS 的时间范围），`check-admin` 里有一条
静态断言钉住"不许再出现第二份"。

### 路径不再靠手填：浏览 + 目录自动补名

三个路径框（基准快照 / 存快照到 / 差异 CSV）都带「浏览」**图标按钮**
（`.pick`，作用写在 `title` 里，悬停可看）：

* **基准快照**选**文件**，按 `.tsv` 过滤 —— 选择器的标题跟着用途走
  （`picker::choose_path`，kind + title + exts），不会再弹出写着
  「选择要监控的文件」的对话框去选快照。
* **存快照到 / CSV** 选**文件夹**，文件名由后端补
  （`analyze_default_path` 同一套命名）。落盘前 `export_target` 统一判断：
  给的是目录就补默认文件名，给的是文件就原样用 —— 把目录当文件写只会
  得到一个 `os error 5`，从报错看不出问题在哪个参数上。

「对比」「保存快照」两个按钮也只用短标签，完整解释放 `title` ——
这一行还排着排序、最小增量两个输入框，长按钮会把别的控件挤换行。

### 存快照 / 对比是后台作业（有进度条）

两个动作在 200 万文件下都是**好几秒**（写 / 读一百多 MB 的 TSV + 归并），
所以与 F12 一样走后台线程：命令只做校验并开工（参数类错误当场返回、
当场弹提示），进度与结果走事件 —— `diff:progress` / `diff:done` /
`diff:saved` / `diff:error`，另有 `diff_status` 供打开视图时补一次状态。

进度条上的百分比是**整件活走到哪了**，不是某一阶段的百分比：四步的量纲
不同（读文件按字节、解析与抓树与归并按条目），各占一段权重
（0.15 / 0.30 / 0.40 / 0.15）。条下面有阶段名（读取快照文件 → 解析快照 →
建立当前快照 → 对比并排序）和**前端自己跳的"已用 x.x 秒"** —— 阶段名要等
节流后的事件，而"还活着"只能靠一个一直在动的数字证明。作业期间两个开工
按钮置灰，进度行空闲时整体收起。

**解析必须有自己的一段**：读文件只占几秒里的一小截，大头在逐行解析上 ——
解析不给进度的话，条会在"读取快照"上僵住，用户看到的正是"只有字、条不动"。
所以引擎把读与解析拆开（`read_to_string_with` + `from_tsv_with`，分母优先
用 `#count` 表头，没有就数换行符），界面上也拆成两个阶段。

引擎侧为此加了带回调的孪生函数（`capture_with` / `load_with` /
`diff_with` / `write_tsv_with` / `save_with` / `from_tsv_with` /
`read_to_string_with`），不带回调的老函数全部委托
到它们 —— CLI 与界面用的是**同一份**实现，两条路分叉的话快照正文就不一样了。
顺带的收益：写快照改成流式（`BufWriter` 直写文件），200 万条不再先拼出
一份一百多 MB 的中间字符串。

流水与预警的每一行都能**双击定位**：在资源管理器里选中该文件
（复用右键菜单的 `contextReveal` → 后端 `reveal_path`，绝不手拼命令行）。
文件已被删除时后端会退到仍存在的上级目录，界面上会如实提示。

监控面板的「阈值预警」可以**向下折叠**（标题栏最右的箭头）：只留标题栏、
条数还看得见，省下的高度自动回到变更流水 —— 高度是"预警退出按权重分配"
让出来的，所以流水那边**没有**对应的规则，改一处就是全部。折叠状态进
偏好文件（`alerts_collapsed`，`#[serde(default)]`）。

### F11 列表的六列与「创建时间从哪来」

差异表是 类型 / 变化 / 文件名 / 修改时间 / 创建时间 / 所在目录 六列：

* **文件名从中间省略，扩展名必须留着**（`fwMiddleEllipsis`，真值表在
  `check-admin.js`）。尾部省略会让 `…- 副本.xlsx` 和 `…- 副本(1).xlsx` 长得
  一模一样 —— 而这两个恰恰是用户要区分的东西。
* **修改时间**来自快照（`old/new_mtime`，已经在 TSV 里）；**创建时间**
  索引里**不采集**（每节点 +8 B，200 万节点就是 16 MB，为一个"列表里显示"
  的字段不划算），所以后台线程在对比结束后对**已经在列出的那几百行**
  逐行 `stat` 一次补上（`fill_ctimes`）。取不到的（已删除、无权限）显示 `—`，
  不会显示成 1970。
* 六列在窄窗口放不下时**横向滚动**，不压成省略号：把时间或文件名压掉，
  等于把这张表要回答的问题抹掉了。

### F13 文件搜索：为什么快，以及正则为什么是自己写的

搜的是**内存里的索引**（`core_index::search`），不是重新遍历磁盘：扫描一次
已经把 200 万个目录项装进了字符串池，搜名字就是扫一遍内存 —— 百万级节点
几十毫秒；重新 `FindFirstFile` 一遍要几十秒，而且两次遍历之间磁盘会变，
结果会和面积图对不上。所以：

* 只有**命中**的节点才拼完整路径（`path_of` 要沿父链建字符串，对 200 万
  个全做一遍等于白烧几百毫秒）；
* 相关度排序：完全相等 > 前缀 > 中间出现；模糊模式按**连续命中**与名字长度
  算分；同分时大文件在前（同样叫 `report.pdf`，多半在找大的那个），再同分
  按名字，保证结果稳定不跳动；
* **正则由引擎自己实现**（`SimpleRegex`，约 150 行）：`crates/**` 零第三方
  依赖，不能引 `regex`；而"搜索"不该只在界面里能用（CLI 早晚要一条同名命令，
  两套正则方言迟早给出不同结果）。支持 `. * + ? [abc] [a-z] [^…] ^ $ \`
  与转义，**不支持** `|`、`()`、`{n,m}` —— 遇到直接报错说清楚，不当字面量。
  回溯有步数预算（`STEP_BUDGET`），`a*a*a*…b` 这种写法会明确报"太复杂"，
  而不是把界面卡死。

### E1~E5：归因 / 详情 / 报告 / 试算 / 风险清单（v0.1.2）

五个功能都遵循同一条规矩：**算法在引擎里，界面只画**。各自的"为什么这样做"：

* **增长归因必须算在 `diff_with` 里面。** `DiffReport.rows` 是被 `top` 截过的
  （界面默认 300 行），而"哪个目录在长"要的是全量变化行 —— 全量只在归并结束
  那一刻存在。所以归因挂在 `DiffOptions::attr` 上、由 `diff` 顺带算完。
  前端**不做二次聚合**：一旦在 JS 里再累加一遍，界面与 CSV/CLI 就会给出两套数。
* **详情面板把"两个时间点"分开说。** 上半截来自扫描时的索引（大小、占用、
  `NODE_*` 属性位），下半截是点击时现场 `stat` 的（创建时间、硬链接数、
  `FILE_ATTRIBUTE_*`）。两套属性位含义完全不同，混着解会把"扫描时压缩"
  显示成"现在压缩"。`frn` 是**十六进制字符串**：64 位整数过 JSON 到 JS 会
  掉精度（超过 2^53），用数字传会显示成一个"看起来合理但错误"的值。
* **报告是一份模板。** `core_scan::report::build_html` 同时给 CLI 与界面，
  产物是单个 HTML：内联样式 + 内联 SVG，没有脚本、没有外链、没有字体文件。
  方块颜色按名次（**越大越深**），不按类型 —— 界面里颜色 = 类型，报告里方块是
  目录，两套语义混用比没颜色更糟，图注里写清楚了。
* **规则试算不带状态。** 判据照抄 `RuleEngine::evaluate`，但**不读也不写**
  触发状态与冷却期。带状态的话"试算一次等于消耗一次冷却"，没人敢点第二次。
  绝对阈值当场有效；增量/速率规则没有监控起点时返回 `judgeable=false`，
  界面显示"要跑满一个窗口才能判断"，而不是"不会触发" —— 后者会被读成
  "阈值设得很安全"。
* **风险清单只看文件名。** `core_index::sensitive` 是纯规则表匹配（7 条规则：
  私钥 / 密码库 / 钱包 / 云凭据 / .env / 包管理器令牌 / 证件），零 IO、毫秒级。
  不读内容这件事必须写在页面上，否则"没找到"会被读成"没有风险"；命中也不等于
  "有问题"，每条都带一句"为什么要看它"。结果类型叫 `Finding` 而不是 `Hit` ——
  与搜索的 `Hit` 同名会让 `check_api` 的符号表互相覆盖，报出一串假错。

### E6：增长趋势与基线异常（v0.1.4）

回答的是"**这块盘这一周在长吗，今天长得正常吗**"——快照对比要人手动存两份才能回答，
而这个功能自己攒数据。

* **只存目录聚合，不存文件清单。** 快照是文件级的（200 万行、上百 MB），每天一份
  留 30 天就是几个 GB，而"盘在长吗"不需要文件级精度。历史每个样本最多 300 行
  （按体积降序），400 个样本封顶，一个月不到 1 MB，还能直接 `cat` 看。
* **分桶按"文件的第 N 层祖先"，不是按相对扫描根的层数。** 命令行只扫
  `C://proj` 时树里只有它以下的节点，按相对层数算的话 `C://proj//src` 会变成
  "第 1 层"，与整卷扫描时的"第 3 层"对不上 —— 同一天一次手动扫子目录、一次后台扫
  整卷，趋势图上就会出现两条同名不同值的线。
* **基线按"天"，不按"同一小时"。** 采样间隔是可变的（改周期、关机、手动记录），
  按小时比会把"这次隔了 3 小时"读成"这 3 小时涨得特别凶"。
  日增量 = 当天最后一个样本 − 上一个有样本的日子，按间隔天数摊平。
* **不足 3 天基线就不给 z 值。** `Anomaly.z` 是 `Option<f64>`，界面显示"差 N 天"。
  这与规则试算里 `judgeable=false` 是同一条原则：不知道就说不知道，
  给 0 会被读成"和基线一样"。
* **σ 有 1 MiB 的下限，z 有 99.9 的上限。** 基线极稳时 z 会算出 850 这种数，
  数学上没错，但"850 和 900 有什么区别"没有意义，只会让人以为程序在胡说。
* **只有性能模式自动记录。** 在别人的盘上定期写文件是有副作用的动作，标准模式
  不该悄悄发生 —— 那边点「记录一次」才写。同一目标 30 分钟内最多自动记一次，
  手动记录不受这个限制（那是用户的明确意图）。
* **历史文件的位置只有一个定义**：`core_scan::history::default_path`
  （`%APPDATA%\FileWatch\history\<key>.tsv`）。CLI 与界面各写一份的话，
  命令行记的样本界面看不见，而且这种问题没人会主动去发现。
* **写盘走 `.part` 再改名。** 半截历史会让趋势线凭空掉下去，看起来像"有人删了
  几百 GB"。

### E7：扫描期渐进渲染（v0.1.5）

全盘扫描要几秒到几十秒。以前这期间画布是空的（只有一个百分比），现在**扫到多少画多少**。

* **引擎按步长回调，并且先聚合再回调**（`PartialSink::tick`）。扫描过程中目录节点的
  `size` 一直是 0（只有文件节点有大小），漏掉聚合就画出一屏 0 面积的方块 ——
  看起来像「扫到的东西全是空的」，比不画还糟。所以聚合与回调绑在一个函数里，
  调用方没有机会漏。
* **两条扫描路径都接**：MFT 每 200k 槽位、目录遍历每 400 个目录。降级模式才是
  普通用户的主场景，只做 MFT 等于大多数人看不到这个功能。
* **只画根的第一层。** 深层的方块在扫描中一直在变，画了也读不下去；
  第一层的相对大小已经足够回答「这块盘大概长什么样」。
* **预览画在独立画布上**（`#scan-preview`，`pointer-events:none`），不碰
  `Treemap` 的状态机：布局每 200 ms 换一次，让正式渲染器读半成品会把
  「当前焦点 / 视图根」搅乱。扫完隐藏这一层，真图照常接管。
* **布局复用 `core_viz::squarify`**，坐标是 0~1 的归一化值。所以预览与扫完之后的
  形状是连续的（不会啪一下变成另一种布法），扫描中改窗口大小也不用重算。
* **后端按 200 ms 节流**：聚合便宜，IPC + 重绘不便宜，5 fps 够了；
  更密只是让画面抖。

## 依赖从哪来（本机的网络情况）

引擎层零依赖，所以 CLI 从不需要联网；**GUI 是第一个真的需要 crates.io 的地方**。
本机实测：

| 目标 | 结果 |
|---|---|
| `index.crates.io`（索引） | 200 |
| `static.crates.io`（真正下载 `.crate`） | **不可达** |
| `registry.npmjs.org` | **不可达** |
| `mirrors.ustc.edu.cn/crates.io`（索引 + 下载） | 200 ✅ |
| `registry.npmmirror.com` | 200 ✅ |

所以配置了两处镜像，都已写好、不需要再手工设置：

* `~/.cargo/config.toml` —— 把 `crates-io` 换成中科大（sparse 索引 + 同一站点的
  下载端点，实测 `.../crates/serde/1.0.210/download` 能拉到 78 KB 的真包）。
  想还原官方源就删掉这个文件，它只做了这一件事。
* 前端**不用 npm**（纯静态文件、无打包器），所以 npmmirror 只是备着没用上。

还有一个**只在沙箱/CI 里才会遇到的坑**：如果 cargo 报
`Failed to connect to ... over proxy 127.0.0.1`，说明它在走一个不可达的代理。
环境的 `https_proxy` 是对的但 cargo 没吃进去（curl 出于 httpoxy 防护会忽略大写的
`HTTP_PROXY`，而沙箱同时设了大小写两套变量），显式喂给它即可：

```bash
CARGO_HTTP_PROXY="$https_proxy" cargo build --release
```

普通终端里不需要这一层。

### 三个必须知道的坑

1. **`icons/icon.ico` 不能少。** `tauri-build` 要拿它生成 Windows 资源文件，
   缺了会直接构建失败（报 `required for generating a Windows Resource file`）。
   这个和工具链无关，GNU/MSVC 都一样。
2. **分发要带上 `WebView2Loader.dll`。** 产物是动态导入它的
   （`objdump -p` 能看到这条 import），`webview2-com-sys` 的构建脚本会自动把它
   复制到 exe 旁边。只拷 exe 会启动即报缺 DLL。系统还需要 **WebView2 运行时**
   （Win11 自带；Win10 通常随 Edge 装机已有，本机实测 145.0.3800.82）。
3. **别用「在 exe 里搜界面字符串」判断前端有没有编进去。** Tauri 2 会把前端
   压缩后嵌入，明文根本搜不到 —— 搜不到就以为"没编进去 / 没重编"，会得出
   完全相反的结论。要确认前端是不是最新的，看构建输出里有没有
   `Compiling filewatch-gui`，或者看上一节那份 dep-info 清单。
   （前端一变就会重编，**不需要**在 `build.rs` 里补 `rerun-if-changed`。）

## 为什么 GUI 不在引擎的 workspace 里

引擎层（`crates/**`）的硬约束是**零第三方依赖**，而 GUI 必然要用 Tauri。
所以 `src-tauri` 自己就是一个 workspace 根，通过 path 依赖引用引擎；
引擎根的 `Cargo.toml` 用 `exclude` 把它挡在外面。效果：

* 在 `filewatch/` 下 `cargo build` 永远不会去编译 Tauri —— 引擎的依赖图仍然是空的；
* 两边可以独立升级、独立构建；
* **只有 `apps/gui/src-tauri` 这一层被允许加依赖**，加之前请确认这一点。

## 交互模型（一个刻意的取舍）

布局是**屏幕空间递归**的：每一层都用当前画布的像素重跑一次，所以目录标题栏恒定
16 px、间距恒定 1~2 px，缩放时装饰不会变形（文档 §5.6）。这带来一个后果 ——
**自由拖拽缩放和它天然冲突**：把整张图当作大位图去缩放，那些「恒定像素」的装饰
就会跟着放大，屏幕空间递归就白做了。

所以这里的「缩放」表达为**层级导航**：

| 操作 | 效果 |
|---|---|
| 滚轮向上 / 双击方块 | 下钻到光标下最深的那个方块（等价于放大） |
| 滚轮向下 / Esc | 回到上一层（等价于缩小） |
| 点击方块 / 点击右侧类型 | 选中并显示详情（不改变层级） |
| 点击类型行 | 高亮面积图里同一扩展名的所有方块，其余降透明度 |
| 上方面包屑 | 任意层级来回跳 |
| 顶栏「细节」滑块 | 调整 LOD 展开阈值（`min_side`）：左=精简，右=展开更深 |

连按滚轮就能一路钻到最深处，这正是 WizTree / SpaceSniffer 的模型，也是这类
「每层铺满视口」的面积图唯一自洽的缩放方式。文档 §5.6 里那套 `(center, zoom)`
相机模型是给「把整棵树当一张无限大画布」的渲染方式准备的，与屏幕空间递归二者
只能选一个 —— 这里选了后者，因为它才是「缩放不变形」的前提。

## 着色（三种模式）与「名字风暴」教训

顶栏「着色」有三档，后端只发**槽位号 + 强度**（`wire.rs`），颜色由前端定：

| 模式 | 后端给什么 | 前端怎么画 |
|---|---|---|
| 按文件类型 | `ext_id % 15` 的槽位（无扩展名归最后一档） | 色板 16 色各占一档，与「文件类型」列表的色块同一份 |
| 按目录深度 | 槽位 = 层级，强度 = 层级/8 | 同一色相由暗到亮 |
| 按文件年龄 | 槽位固定 0，强度 = 年龄/3 年 | **热力图色带**（红→橙→黄→绿→青→蓝），顶栏有「新→旧」图例 |

两个真实教训，各自有测试与静态检查守着：

1. **「整片同色」**：`ExtensionTable::id_of_node` 拿整个文件名去查以扩展名为键的表，
   永远查不到 → 每个文件都落到「其他」桶 → 按类型着色时整张图一个颜色。
   它不会让编译失败、也不会让既有测试变红（原来的测试只断言「槽位在范围内」，
   而上限永远满足），只有眼见才会发现。现在的测试断言的是「不同扩展名拿到
   不同槽位」，`check-admin.js` 还会把下拉框的取值与 `shading_of()` 的分支对齐
   —— 那个函数对不认识的值**静默**回落到按类型着色，选了没反应就是这类问题。
2. **「文件夹树列表加载太慢」**：原因不在后端（`tree_rows` 最坏 240 µs、布局
   5 ms，见下面的性能探针），而在前端每个方块各发一次 `node_detail` 取名字，
   且每回来一个就整图重画一次 —— 几千个方块就是几千次 IPC 往返 + O(N²) 遍历。
   现在是布局之后由 `primeNames()` 调一次 `node_names` **批量**取回，
   `cachedName()` 只读缓存；`goto()` 也改成先画列表再算图，点目录立刻有反应。
   对应的守卫：`treemap.js` 里不允许出现 IPC 调用、`cachedName` 体内不允许
   `await`/`call`。

性能探针（需要真实大目录，默认不跑）：

```bash
cd apps/gui/src-tauri
cargo test --release -- --ignored --nocapture perf_probe   # 默认 C:\Windows\System32
FW_PROBE_DIR=D:\某目录 cargo test --release -- --ignored --nocapture perf_probe
```

它量的是每个环节的耗时（扫描 / 派生索引 / `tree_rows` / 布局 / 单点查询），
并把**按类型着色的色槽分布**打出来 —— 分布只有一档就说明着色又坏了。

## 二进制布局协议

Rust → 前端**不走 JSON**（文档 §5.6）：200 万节点的 JSON 会卡死主线程、体积也
膨胀数倍。协议在 `src-tauri/src/wire.rs`，前端解码端在 `src/wire.js`，两边必须
同步改：

```
头部 16 字节：magic "FWLY" | version | count | root
每项 56 字节：node u32 | depth u8 | flags u8 | slot u8 | pad u8
              ext_id u32 | shade_t f32 | rect 4×f32 | header 4×f32 | size u64
```

前端 `decode` 的第一件事就是校验 magic 与 version，不匹配**直接抛错**而不是按旧
偏移读出一堆「看起来差不多」的错数据。`wire.rs` 里有一个把每个字段都解回来的
往返测试（`round_trip_preserves_every_field`），它就是这份文档的可执行版本。

## 与 CLI 的关系

同一个引擎、同一条装配路径（`core_scan::Session`）。所以：

* 同一个目录在 CLI 与界面里显示的大小**必须**一致 —— 不一致就是 bug，不是"口径不同"；
* 界面里的任何新算法都应该先落到 `core-*` 里，两个前端共享；
* 反向也成立：GUI 这一层不允许出现「顺手在这里算一下」的逻辑。

齐全后一次提交并以 160ms 渐变衔接；系统启用减少动态效果时不播放渐变。
渲染回归检查：`node apps/gui/tools/check-rendering.js`（只在内存中运行）。

实时监控支持停止后重新启动；复用扫描时建立的监视器也会收集变更行。
监控目标必须精确匹配已扫描的目录，错误路径不会自动扩大为整盘监控。
空闲时持续更新运行状态，变更流水按最新事件在前排序，事件突发时从缓冲回填。
若出现队列丢弃，界面会显示数量并提示重新扫描校准。轮询间隔为 100–60000 毫秒。

测试删除只允许在本次独占创建的测试目录中进行；测试目录具有所有权标记，
清理前核验规范路径、目录边界及重解析点，检查失败时保留目录。
具体约束见 `tools/TEST_SAFETY.md`（仓库根目录）。

新增前端回归检查：`node apps/gui/tools/check-monitor.js`、`node apps/gui/tools/check-appearance.js`。

### 独立监控与路径导航

「实时监控 → 监控方式 → 独立监控 · 固定路径」可管理最多 32 个文件/文件夹。
每项支持新增、修改路径/规则、暂停/启用与移除。配置自动保存在
`%APPDATA%\FileWatch\independent-monitor.json`，下次启动恢复已启用的目标；
移除只移除监控定义，不操作目标文件。切换页签或监控方式不会停止后台监控。

独立监控不使用面积图的扫描状态或锁，不打开卷设备、不创建 USN Journal、
不读取文件内容或锁定文件写入。文件监控只监听父目录并筛选指定路径；文件夹
需要先遍历元数据建立自己的索引（默认上限 30 万节点），随后用目录通知增量更新。
建立大目录索引仍会消耗磁盘读取、CPU 与内存；权限不足、来源中断或队列溢出
会显示等待/异常并尝试恢复；目录超出预算或无法建立通知来源时停止自动重试，
避免反复全量扫描，缩小范围或检查权限后重新启用。固定文件被移走后等待原路径重现，不跟随文件改名。

变更流水和预警按 Windows 当前本地时区显示 `年-月-日 时:分:秒.毫秒`，
回填历史记录保持原始时间。流水与预警仅保留内存中的最近记录，退出后清空。
阈值规则旁的「?」说明三类规则、单位、基线和抑制机制：规则之间为**或**，
严格大于阈值才触发，默认需回落至阈值 90% 以下且经过 10 分钟冷却才可再次触发。
速率规则使用“本窗口累计净增长 / 配置窗口长度”，并非瞬时写入带宽。

文件夹树顶部输入完整路径后按 Enter 或「→」前往已扫描的目录；路径必须精确
存在，不会退回祖先目录。面积图路径栏右侧显示当前实际绘制的方块数。
大文件列表双击会在面积图与文件夹树中前往该文件的父目录，并保留文件详情。

独立监控、时间、异步回填、扫描隔离与路径跳转回归：
`node apps/gui/tools/check-independent.js`（纯内存）。

### 按对象提供右键操作

| 右键位置 | 常用操作 |
| --- | --- |
| 文件夹树、面积图方块、大文件、面包屑、详情 | 查看详情、进入文件夹/前往所在目录、**打开方式…**、**用默认程序打开**（仅文件）、在文件资源管理器打开、资源管理器定位、复制完整路径/名称/大小信息、加入独立监控、返回上级和刷新面积图 |
| 面积图空白处 | 返回上级、返回扫描根、刷新面积图、取消高亮 |
| 盘符 | 扫描此盘符、在文件资源管理器打开、资源管理器定位、复制根路径/容量、预填独立监控 |
| 文件类型 | 高亮此类型、取消高亮、复制数量和大小统计 |
| 独立监控目标 | 编辑路径与阈值、暂停/启用、复制规则、打开方式…、定位目标、移除监控定义（保留文件） |
| 变更流水、阈值预警 | 复制含本地时间及完整路径的记录、打开方式…、在文件资源管理器打开、定位所在目录、加入独立监控；独立流水还可查看所属监控 |
| 快照对比的差异行 | 在文件资源管理器打开、定位所在目录（面积图/资源管理器）、复制完整路径/名称、复制本行变化（类别 + 增量 + 前后大小 + 路径） |

**「打开方式…」与「用默认程序打开」是 v0.1.1 加的、唯一会真正打开文件的两项**
（其余动作都只碰资源管理器窗口）。前者弹系统原生的 `SHOpenWithDialog`：候选程序
由 Windows 自己列出，选中的程序也由系统执行 —— 前端不读注册表、不猜关联。后者
等于双击，因此**可执行扩展名（exe/bat/cmd/ps1/vbs/lnk/reg/…）在菜单里不出现**
这一项，只留「打开方式…」，让用户在系统对话框里再确认一次。两项都由后端
`file_target` 统一把关：目标不是已存在的文件（文件夹、已被删除的文件）一律拒绝
并给出提示，绝不用"上级目录"顶替用户点的那个文件。文件夹没有「打开方式」。

**「在文件资源管理器打开」与「在资源管理器中定位」是两件事**：前者打开这个文件夹
（目标是文件时打开它**所在的目录** —— 把文件交给 `open` 动词等于用默认程序执行
它，.exe 就直接跑起来了）；后者打开上级目录并**选中**目标，用来看清它在哪、周围
有什么。两者都走原生外壳接口（`ShellExecuteW` / `SHOpenFolderAndSelectItems`），
不拼命令行、不执行文件。

“加入独立监控…”会打开预填路径的编辑器，保存后生效；相同路径已有监控时编辑
原目标，不重复添加。联动监控或扫描进行中，盘符菜单里的扫描操作不可用。
菜单支持 Shift+F10/菜单键、上下方向键、Home/End、Enter，Esc/Tab 关闭；
点击外部、滚动或缩放窗口也会关闭。输入框保留系统文字编辑右键菜单。
菜单随主题变化，并自动避让窗口边缘；目标名称通过纯文本赋值，不解析 HTML。

资源管理器定位使用原生 PIDL 选择接口，不执行文件、不拼接命令行；目标已删除时
定位最近仍存在的上级目录并提示。复制权限不可用时会展示已选中的只读文本供 Ctrl+C。
当前右键操作不修改或删除目标文件。回归：`node apps/gui/tools/check-context.js`，
覆盖异步右键竞争、过期扫描、目标操作、完整路径、剪贴板降级、边缘定位和键盘行为。
